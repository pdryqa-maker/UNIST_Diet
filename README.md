# 🥗 UNIST Diet

UNIST **기숙사식당 · 학생식당 · 교직원식당**의 아침/점심/저녁 식단을 불러와
메뉴별 **탄수화물 · 단백질 · 지방 · 당류**를 추정하고, 어떤 식당의 식단이 다이어트에 적합한지
**0.0–10.0점(이전 식단 평균 = 5.0점)** 으로 보여주는 React 대시보드입니다.

> 밥먹어U 앱은 식단별 칼로리만 제공합니다. 이 프로젝트는 메뉴명으로 3대 영양소와 당류를 추정해 칼로리 너머를 비교합니다.

## 주요 화면

| 영역 | 내용 |
| --- | --- |
| 오늘의 추천 | 선택한 날짜·끼니에서 점수가 가장 높은 식당/메뉴 |
| 식단 분석 카드 | 식당·메뉴(한식/할랄/간편식/일품)별 점수, kcal, 탄·단·지 에너지 구성, 당류, 점수 요인(칼로리·단백질·당류·지방이 평균 대비 ± 몇 점), 메뉴별 추정 영양표 |
| 주간 점수표 | 요일 × 끼니 × 식당 히트맵 (칸 클릭 → 상세) |
| 식당별 비교 | 주간 평균 점수 순위, 한 끼 평균 영양 구성 |
| 주별 추이 | 식당별 주간 평균 점수 라인 차트 (표 보기 지원) |
| 분석 방법 | 추정·보정·점수화 방식과 기준 기간 |

## 데이터

- 참고한 원 백엔드: [mad-unist/unist-meal-backend](https://github.com/mad-unist/unist-meal-backend) (Django)
  - `Menu(place, type, time, content, calorie, date)` 모델, `/menu/v1/menus` · `/menu/v1/today-menus` API
  - 식당이 올린 주간메뉴표 엑셀(`주간메뉴표` 시트)을 파싱하는 구조. **Heroku 서버는 현재 종료**되어 응답하지 않습니다.
- 현재 밥먹어U 앱([HeXA-UNIST/meal_client](https://github.com/HeXA-UNIST/meal_client))이 쓰는 공개 API를 사용합니다.
  - `GET https://meal.hexa.pro/v2/menu` (이번 주), `GET https://meal.hexa.pro/v2/menu/<YYYY-MM-DD 월요일>` (지난 주)
  - `cafeteria(DORMITORY/STUDENT/FACULTY) → meals(date, timeType) → menusByType(KOREAN/HALAL) → sections(REGULAR/SPECIAL/CONVENIENCE, calorie, menus)`
- `scripts/fetch-menus.mjs`가 과거 주를 거슬러 올라가며 모아 `public/data/menus.json`에 저장합니다. 기존 스냅샷과 병합하므로 API에서 오래된 주가 사라져도 기록이 남고, 이 기록이 점수 표준화의 기준이 됩니다.
- 페이지를 열면 이번 주(와 공개된 다음 주) 식단을 API에서 실시간으로 다시 받아 합칩니다 (API가 CORS `*` 허용).
- **이전 주 아카이브 (2025-11-24 ~ 2026-06-22)**: API는 2026-06-29부터만 제공하므로, 밥먹어U 운영팀의
  [HeXA-UNIST/BapuServerlessApi](https://github.com/HeXA-UNIST/BapuServerlessApi) `menus/`(식단표 이미지를 Gemini로 OCR한 JSON)를
  `scripts/import-archive.mjs`로 가져와 API에 없는 주만 채웁니다 (커밋 `5fb3bb8` 고정).
  - 신뢰도: API와 겹치는 375끼 중 372끼의 공시 칼로리가 정확히 일치(나머지 ±1kcal), 메뉴명도 대부분 동일.
  - 정리: `<천원의 아침밥>` 같은 섹션 제목 → 제목으로, `<간편식 25개 한정>` 이후 → 간편식 섹션으로 분리, `배추김치/요구르트`처럼 `/`로 붙은 메뉴 분리,
    1월 초 날짜의 연도 오류 보정, 250–2,500kcal 밖의 칼로리 오독(104, 9,630 등) 제외.
  - 대시보드에서는 해당 주에 `OCR 아카이브` 표시가 붙습니다.
  - 해당 레포에는 라이선스 표기가 없습니다.

## 분석 방법

### 1) 영양 성분 추정 — `src/lib/nutrition.js`

1. 메뉴명을 해석합니다: `큰그릇)`·`미니` → 양, `*케찹`·`&타르S`·`*참깨D` → 소스/드레싱, `2EA` → 개수, `(소고기,당면,…)` → 설명 제거.
2. 조리법·주재료 규칙 102개 + 소스 규칙 11개 중 처음 맞는 규칙으로 단체급식 1인분 기준 `[탄수화물, 단백질, 지방, 당류] g`을 붙입니다.
   (예: `돈까스` 26/22/24/4, `찌개` 8/10/8/2, `나물·무침` 4/1.5/2/1.5, `아이스티` 19/0/0/18)
   값은 식품의약품안전처 식품영양성분 DB의 대표 음식값을 급식 배식량에 맞춘 근삿값입니다.
3. 밥이 함께 나오는 식단의 면·일품 요리는 반찬 크기(0.5인분)로 봅니다.
4. **`추가밥`은 합계에 포함합니다.** 면 요리 끼니 221개를 비교하면 추가밥이 붙은 104끼는 공시 칼로리가 메뉴 추정보다
   밥 한 공기만큼(+262kcal) 높고, 밥을 더하면 차이가 −14kcal로 사라집니다 → 공시 칼로리에 추가밥이 포함되어 있습니다.
   이때 면·일품 요리는 한 그릇 그대로 둡니다.
   (처음엔 판단이 안 됐는데, 추가밥이 주로 면 요리에 붙고 면 요리 추정이 약 10% 높아 두 효과가 상쇄됐기 때문입니다.)
5. **칼로리 보정**: 추정 합계 kcal(4C+4P+9F)이 식당 공시 칼로리와 같아지도록 전체를 같은 비율로 조정합니다.
   → 총 에너지는 공시값, 영양소 구성비는 메뉴 구성에서 나옵니다.
   - 공시 칼로리가 없으면(간편식 등) 전체 보정계수 중앙값(현재 ×1.09)을 적용합니다.
   - `숯불향닭다리구이` 한 줄에 1,507kcal처럼 밥·반찬이 생략된 표기는 보정계수를 ×1.6까지만 키우고 남는 에너지를 단체급식 평균 구성비(탄 55%·단 16%·지 29%·당 8%)로 채웁니다.

현재 데이터(2025-11-24 ~ 2026-10-11, 46주, 2,244개 식단, 메뉴 13,665개)에서 규칙 매칭률은 **99.9%** 입니다
(`npm run report -- --unmatched`로 확인).

### 2) 다이어트 적합도 점수 — `src/lib/scoring.js`

| 지표 | 방향 | 가중치 |
| --- | --- | --- |
| 칼로리 (kcal) | 낮을수록 좋음 | 0.35 |
| 단백질 에너지 비율 | 높을수록 좋음 | 0.30 |
| 당류 에너지 비율 | 낮을수록 좋음 | 0.20 |
| 지방 에너지 비율 | 낮을수록 좋음 | 0.15 |

1. 각 지표를 **이전 식단(이번 주 월요일 이전 전체)의 같은 식사시간(아침/점심/저녁)** 분포로 z-점수화하고 가중합합니다.
2. 그 원점수를 다시 기준 기간 분포로 표준화해 `점수 = 5 + 2·z` → 0~10으로 자르고 소수점 한 자리 반올림.
3. 결과: 기준 기간 평균 **5.00점**, 표준편차 **2.0점** (아침·점심·저녁 모두 검증).
4. 식당 점수 = 해당 기간 그 식당 모든 메뉴 점수의 평균. 끼니별 추천 = 그 시간 최고점 메뉴.

| 점수 | 구간 |
| --- | --- |
| ≥ 7.0 | ▲▲ 매우 적합 |
| 5.5 – 6.9 | ▲ 적합 |
| 4.6 – 5.4 | ● 보통 |
| 3.1 – 4.5 | ▼ 주의 |
| ≤ 3.0 | ▼▼ 부적합 |

### 한계

메뉴명 기반 추정치이므로 실제 레시피·배식량과 다를 수 있습니다. 점수는 UNIST 식당 간 **상대 비교**용이며 의학적 영양 평가가 아닙니다.

## 실행

```bash
npm install
npm run dev          # http://localhost:5173
npm run fetch-data   # 밥먹어U API에서 스냅샷 갱신
npm run import-archive  # HeXA OCR 아카이브로 API 이전 주 채우기 (재실행해도 결과 동일)
npm run report       # 분석 요약 (식당별 평균 점수·영양, 매칭률)
npm run build        # dist/ 정적 빌드
```

## 배포

`.github/workflows/deploy.yml`이 `main` 푸시와 **매일 06:00 KST**에

1. 최신 식단 스냅샷을 받아 바뀐 경우 커밋하고
2. 빌드해 GitHub Pages에 배포합니다.

## 구조

```
src/
  lib/menu.js         API 응답 → 식단 옵션 평탄화, 식당·끼니 상수, 날짜 유틸
  lib/nutrition.js    메뉴명 → 탄/단/지/당 추정 규칙, 칼로리 보정
  lib/scoring.js      다이어트 적합도 점수 (기준 기간 표준화)
  lib/dataset.js      스냅샷 + 실시간 API 로딩 → 분석 → 점수
  lib/aggregate.js    식당별/주별 집계
  components/         대시보드 UI (React, Recharts)
scripts/
  fetch-menus.mjs     밥먹어U API 스냅샷 수집 (매일 Actions)
  import-archive.mjs  HeXA OCR 아카이브로 API 이전 주 채우기
  report.mjs          분석 요약 CLI
public/data/menus.json  주간 식단 스냅샷
```
